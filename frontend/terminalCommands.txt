=== SAVE YOUR CHANGES (COMMIT & PUSH) ===
git status                (Check what changed)
git add .                 (Add all changes)
git commit -m "message"   (Commit)
git push                  (Push to GitHub)

=== FULL WORKFLOW (Pull → Work → Commit → Push) ===
git pull origin Frontend  (Get latest Frontend - DO THIS DAILY)
[Make your changes in VS Code]
git status                (Check changes)
git add .                 (Add changes)
git commit -m "message"   (Commit)
git push                  (Push to GitHub)

=== WHEN A PAGE IS COMPLETE → MERGE TO Frontend ===
git checkout Frontend
git pull origin Frontend
git merge your-branch-name
git push
git checkout your-branch-name

=== FIX MERGE CONFLICTS ===
git pull origin Frontend   (Pull - conflicts will show)
[Open files with conflicts - look for <<<<<<< HEAD]
[Keep the code you want, delete the rest]
git add .                 (Mark as resolved)
git commit -m "Resolved merge conflicts"
git push

=== SWITCH BRANCHES ===
git branch                (See current branch)
git checkout other-branch (Switch to other branch)
git pull                  (Get latest from that branch)
git checkout your-branch  (Switch back)

📝 TEAM RULES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. git pull origin Frontend EVERY DAY before coding
2. When a page is complete → MERGE to Frontend
3. Don't let your branch fall behind
4. git status often - know what you're about to commit
5. Commit small and often - easier to undo
6. Write clear commit messages: "Fixed navbar bug" not "stuff"
7. Test before pushing - make sure your code works
